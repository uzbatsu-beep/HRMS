# TWM — план усиления безопасности и подготовки к пилоту

**Версия:** 0.3 · **Дата:** 2026-11-19  
**Текущая применимость:** development/test с синтетическими данными. План не является утверждением, что продукт безопасен для реальных работников или управления опасными процессами.

## 1. Известный baseline и границы

- Реализовано: Argon2id, 8-часовая отзываемая серверная сессия, HttpOnly/SameSite=Strict cookie, Secure вне dev/test, CSRF для mutations; серверное разграничение enterprise/unit и часть exact-unit permissions; audit критичных событий.
- Не подтверждены SSO/MFA, защищённая production-конфигурация, политика retention/PII, реально проверенный backup/restore, безопасное хранилище файлов и их антивирусная проверка.
- `docker-compose.yml` — только локальный dev: `--reload`, Vite dev server, демонстрационные значения пароля БД. Порты ограничены loopback; не считать это production-контуром.
- Технический статус `on_hold` не взаимодействует с ПЛК, роботами, interlock и не создаёт сертифицированную Safety-функцию.

## 2. G1 — обязательные engineering changes (предлагаемый PR #28)

| ID | Мера | Проверка завершения |
|---|---|---|
| SEC-01 | `/auth/login`: ограничение попыток по доверенному ключу и контролируемый backoff; не полагаться на произвольный X-Forwarded-For | Негативные тесты превышения лимита, окна разблокировки, равные ответы для неизвестного/неверного пользователя |
| SEC-02 | Явная матрица субъект × enterprise × unit × operation для всего API; unit transfer и grant revoke должны действовать при следующем запросе | Прогоны cross-tenant, negative read/write, stale-session, self-approval |
| SEC-03 | Проверка CSRF и Origin для мутирующих запросов, без обхода через дополнительные маршруты | Негативные тесты на отсутствие/подмену CSRF и чужой Origin |
| SEC-04 | Аудит чувствительных операций без токенов и избыточных ПДн; политика scrub/redact | Тесты на отсутствие cookie, паролей, токенов, документов в выдаче логов |
| SEC-05 | Security checklist для зависимостей и конфигурации; проверка отсутствия секретов в git | Подтверждённая CI-проверка и review |
| SEC-06 | Отдельный тест на обработку ошибок: запрещённые объекты не раскрываются через различия в ответах и detail | Negative integration tests с двумя предприятиями |

Новые механизмы не должны блокировать E2E bootstrap и локальную разработку случайным образом: тестовая среда и политика доверенных прокси задаются явно, но нельзя ослаблять серверные полномочия.

## 4. GitHub — отдельное действие владельца

На 2026-11-19 API сообщил: `main protected=false`, список repository rulesets пуст. Требуется включить GitHub ruleset на `main` с PR-only изменениями, запретом force-push/delete, обязательными заданиями:
- `Backend - lint, migration and tests`
- `Frontend - typecheck and build`
- `Browser E2E - Chromium and synthetic data`

Проверка branch protection endpoint через подключение ответила 403 (недостаточно прав интеграции для чтения), но flags ветки и пустой список rulesets доступны. **Не заявлять, что настройка выполнена, пока правила не включены и не проверены на тестовом PR.**

## 6. Решение о пилоте

**Пилот отклоняется по умолчанию**, пока не закрыты все применимые P0, не определён состав персональных данных, не подтверждены права пользователей и внешняя процедура фактического допуска к работам. Ответственный владелец должен утвердить протокол [приёмки](ACCEPTANCE_PLAN.md), границы внедрения и остаточные риски.

Разработка PR #28 не предполагает изменения действующих данных или автоматического слияния.
