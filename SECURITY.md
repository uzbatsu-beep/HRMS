# Сообщения о проблемах безопасности

TWM разрабатывается и проверяется на синтетических данных. Сообщения принимаются для текущей ветки `main`. Если проблема обнаружена на другой ревизии, укажите её SHA.

## Как связаться с сопровождающим

1. Откройте [Security проекта](https://github.com/uzbatsu-beep/HRMS/security). Если доступна кнопка **Report a vulnerability**, передайте сведения через приватную форму GitHub.
2. Если кнопки нет, создайте [запрос на закрытый контакт](https://github.com/uzbatsu-beep/HRMS/issues/new?title=Security%20contact%20request) с одной фразой «Прошу предоставить закрытый канал для сообщения». Дождитесь ответа владельца `@uzbatsu-beep` о способе связи. Технические сведения передавайте только в согласованном закрытом канале.

## Что приложить в закрытом канале

Укажите ревизию, затронутый модуль, роли и вымышленные подразделения, ожидаемую границу доступа и наблюдаемое поведение. Например, менеджер участка видит запись за пределами разрешённого подразделения. Для диагностики достаточно обезличенных примеров. Удалите из вложений cookies, токены, пароли, данные работников и внутренние адреса предприятия.

Сопровождающий уточняет затронутые версии с автором сообщения и согласует публикацию подробностей после проверки исправления.
